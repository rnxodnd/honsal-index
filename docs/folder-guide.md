# 폴더 이용 방법과 작업 시작 순서

확인일: 2026-10-30. 기획 문서·기본 설정·Python 3.12 환경 설치 안내와 춘천 의료·교통시설 정제 CSV가 준비되어 있습니다. 시설 선택 컴포넌트와 개인화 집계 함수도 추가했습니다. 격자별 접근성 점수 생성과 최종 화면 연결은 진행할 작업입니다.

현재 분석 범위는 생활시설·의료·교통·여가시설 네 항목입니다. 상권 자료에서 생활·여가의 세부 업종을 정리하고, 사용자가 선택한 종류만 분석합니다. 안전성·주거 부담·별도 생활서비스 항목은 이번 범위에서 제외합니다. 공통 규칙은 [시설 선택과 분석 규칙](facility-selection.md)을 참고합니다.

## 현재 있는 폴더

| 폴더 | 담당 | 넣을 내용과 이용 방법 | 현재 상태 |
| --- | --- | --- | --- |
| `app/` | 팀원 2: 프론트엔드 | 시설 종류·지역 선택, 지도, 점수 표시, 비교표, 가중치 입력 화면. 선택 조건과 점수 계산은 `src/`의 함수를 호출 | `facility_filters.py`에 세부 시설 선택 컴포넌트 |
| `src/` | 팀장 + 팀원 3 | 팀장은 점수·추천 코드, 팀원 3은 재실행 가능한 수집·정제 코드를 작성. 담당별 하위 폴더로 구분해 작업 | 교통 추출·공통 시설 분류·선택 점수 집계 코드 |
| `config/` | 팀장 | 계산에 사용하는 설정 보관. `weights.json`에서 기본 가중치를 관리하고 화면에 같은 값을 사용 | 기본 가중치 초안 있음 |
| `data/raw/` | 팀원 3: 데이터 | 제공 기관에서 받은 원본을 보관. 원본을 덮어쓰지 않고 정제 결과는 별도 저장 | 교통 원본은 개발 PC에 보관하며 Git에서 제외 |
| `data/processed/` | 팀원 3 생산, 팀장·팀원 2 사용 | 코드·좌표·단위 등을 맞춘 자료. 백엔드와 화면이 합의한 형식으로 읽음 | 의료·교통 CSV 6개와 공통 분류·유형 목록·준비 상태 CSV 3개 |
| `notebooks/` | 팀원 3 + 팀장 | 데이터 탐색, 결측 확인, 산식 실험용 노트북. 반복 실행할 정제·계산 로직은 검증 후 `src/`로 옮김 | `.gitkeep`만 있음 |
| `docs/` | 팀원 1: 기획·발표, 전원 참고 | 원본 기획안, 개발 일정, 역할표, 데이터 설명, 사용자 흐름, 검증 기록 | 기획안과 계획·역할 문서 있음 |
| `.vscode/` | 팀장 | 팀에서 공유할 VS Code 설정과 확장 추천. 개인 PC의 절대경로는 공용 설정에 넣지 않음 | Python·Jupyter 확장 추천과 `.venv` 경로 설정 있음 |
| `.venv/` | 각 팀원 | 자기 PC 전용 Python 3.12와 설치 패키지. GitHub 공유 대상이 아니며 각자 생성 | 개발 PC에 구성·검증 완료 |

`.gitkeep`은 빈 폴더를 Git에 남기기 위한 자리표시자입니다. 실행 파일이나 데이터가 아닙니다.

## 최상위 파일

- `README.md`: 프로젝트 소개, 팀 역할, 문서 링크, macOS·Linux·Windows 환경 설치 방법. 앱 구현 후 실행 명령도 추가합니다.
- `requirements.txt`: 개발 PC에서 검증한 패키지 버전 목록. 각 팀원은 자기 가상환경에 `python -m pip install -r requirements.txt`로 설치합니다.
- `.python-version`: 사용할 Python 버전 `3.12`를 기록합니다. 이 파일 자체가 Python을 설치하지는 않습니다.
- `.gitignore`: Git에 올리지 않을 파일과 폴더를 지정합니다. 팀장이 공유 정책에 맞춰 관리합니다.
- `config/weights.json`: 생활시설 5/14·의료 3/14·교통 2/7·여가시설 1/7의 기본 가중치 초안입니다. 기존 활성 네 항목의 상대 비중을 합 1로 재조정했으며 검증된 측정 척도는 아닙니다. 무선택 항목은 제외하고 남은 가중치를 다시 조정합니다.

다음 항목은 역할 계획에 등장하지만 현재 로컬에는 아직 없습니다.

- `presentation/`: 팀원 1이 발표자료 원본과 제출용 PDF를 저장할 때 생성.

## 먼저 해결할 연결·공유 사항

### GitHub 연결

이 `honsal-index` 폴더 자체가 Git 기준 위치입니다. `origin`은 팀 GitHub 저장소에 연결되어 있고, 로컬 `main`은 `origin/main`을 추적합니다. Git 명령은 이 프로젝트 폴더 안에서 실행합니다.

팀 저장소는 [rnxodnd/honsal-index](https://github.com/rnxodnd/honsal-index)입니다. 기존 README의 기획 내용과 이 폴더의 환경 설치·역할·문서 안내를 병합했습니다. 팀원들은 README의 Clone·환경 설치 절차를 사용합니다. 기존 Clone이 있다면 작업 중인 변경을 먼저 확인하고 최신 파일을 Pull로 받습니다.

### 데이터 공유

현재 `.gitignore`는 원본 데이터와 나머지 정제 데이터를 기본적으로 제외하며, 춘천 의료·교통 CSV 6개와 공통 분류 관련 CSV 3개를 공유 대상으로 지정합니다. 다음 의료 자료 3개의 기준일은 2026-09-30이며, 제공기관은 건강보험심사평가원입니다. 각 CSV에 원본 파일명·출처 URL·기준일을 포함했습니다.

- `data/processed/chuncheon_hospitals.csv`: 의료기관 380개. 의원·치과·한방·보건기관 등을 `facility_type`으로 구분합니다.
- `data/processed/chuncheon_pharmacies.csv`: 약국 144개.
- `data/processed/chuncheon_medical_facilities.csv`: 위 두 자료를 합친 524개. 지도·백엔드에서는 이 통합 파일 하나를 사용하면 됩니다.

세 파일을 모두 합쳐 읽으면 같은 시설이 중복 집계됩니다. `source_dong`은 원본 읍면동 명칭이며 행정동으로 배정한 결과가 아닙니다. `has_coordinates`는 좌표 존재 여부입니다.

교통 자료는 다음 3개입니다. 전철과 ITX가 공유하는 역은 하나의 시설로 기록하고 `has_itx`로 ITX 정차 여부를 구분합니다.

- `data/processed/chuncheon_bus_stops.csv`: 버스 정류장 1,890개.
- `data/processed/chuncheon_rail_stations.csv`: 춘천 경춘선 역 6개.
- `data/processed/chuncheon_transport_facilities.csv`: 버스와 철도역을 합친 1,896개. 프로그램에서는 이 통합 파일 하나를 사용합니다.

출처·기준일·컬럼 의미·재추출 방법은 [교통 데이터 설명](transport-data.md)을 참고합니다. 팀원들은 Pull 후 정제 CSV를 바로 사용할 수 있습니다.

현재 분석 화면의 입력은 `data/processed/chuncheon_facilities_classified.csv` 하나로 통일합니다. 의료·교통 2,420개에 `analysis_category`와 `analysis_subtype`을 붙인 파일이며, 기존 개별·통합 파일을 여기에 다시 합치지 않습니다. `facility_type_catalog.csv`는 14개 세부유형의 요약, `facility_dataset_status.csv`는 네 항목의 준비 상태입니다. 상권이 아직 없는 생활·여가의 시설 수는 빈 값으로 표시했습니다. 자세한 분류·추가 방법은 [시설 선택과 분석 규칙](facility-selection.md)을 참고합니다.

팀장과 팀원 3은 공개·배포 가능한 작은 정제 파일을 선별해 Git 추적 예외로 추가할지, 별도 공유 위치와 다운로드 절차를 사용할지 정합니다. 최종 제출 프로그램이 필요한 데이터를 실제로 받을 수 있어야 합니다. 전체 데이터 폴더를 무조건 강제로 추가하지 않습니다.

## 지금 시작할 작업

1. **팀장:** 정확한 팀 저장소와 Clone 위치를 확인하고, 네 명이 같은 기본 코드를 받도록 정리합니다.
2. **전원:** 확정한 춘천·네 항목 범위에서 시설 종류 선택 → 지도·점수·비교·추천 흐름을 맞춥니다.
3. **팀장·팀원 2·팀원 3:** 지역 식별 코드, 시설 ID·분석용 세부 종류·원본 업종 코드, 계산 함수의 입력·출력을 합의합니다. 사용자 선택 목록, 위도·경도, 지표 값·단위·출처·기준일·결측 표시를 함께 맞춥니다.
4. **팀장:** 준비된 Python 3.12 환경을 사용해 테스트용 입력으로 점수·추천 함수를 작성합니다. 팀원들의 의존성 설치 결과를 확인합니다.
5. **팀원 1:** 문제 정의, 사용자 시나리오, 발표 목차, 제출 규정을 정리합니다. 16시까지 데이터 출처 조사를 지원합니다.
6. **팀원 2:** 테스트 결과로 지역 선택·점수·비교·가중치 화면을 만듭니다.
7. **팀원 3:** 상권 자료를 생활시설·여가시설의 세부 종류로 매핑합니다. 당구장·볼링장·탁구장을 구분하고 원본 시설 행·업종 코드·좌표를 보존합니다. 의료·교통 자료와 연결할 형식으로 전달하며 테스트 자료는 명확히 표시하고 분리합니다.

팀장과 프론트엔드 담당자는 실제 데이터가 완성되기를 기다리지 않고 합의한 입력·출력으로 병렬 개발합니다. 같은 점수 계산을 화면과 백엔드 양쪽에 따로 구현하지 않습니다.
