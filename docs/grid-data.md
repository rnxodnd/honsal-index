# 격자·주소 조회 통합 안내

팀의 `feature/grid` 작업과 시설 선택·분류 작업을 통합했습니다.

## 공유된 자료와 코드

- `data/raw/chuncheon_dong.geojson`: 춘천 행정동 25개의 경계. 파일 내부 이름은 `HangJeongDong_ver20261001`입니다.
- `data/processed/grid_500m_filtered.csv`, `.geojson`: 500m 후보 격자 2,526개. 두 파일의 ID·개수 일치와 중복·도형 유효성을 확인했습니다.
- `src/make_grid.py`: 경계로부터 500m 격자와 중심점 좌표를 생성합니다.
- `src/filter_grid.py`: SGIS 1km 인구·가구 자료로 후보 격자를 추립니다.
- `src/locate.py`: 주소/장소명 검색, 좌표의 격자 ID, 주변 3×3 격자 ID를 구합니다.

격자 ID는 `G500_{x0}_{y0}`이며 좌표 계산에는 EPSG:5179를 사용합니다. 지도 표시용 좌표는 EPSG:4326입니다. 공개된 격자 파일은 바로 읽을 수 있으므로 매번 원본 통계에서 다시 생성할 필요는 없습니다.

## 재생성

프로젝트 루트의 Python 3.12 가상환경에서 실행합니다.

```bash
python src/make_grid.py --boundary data/raw/chuncheon_dong.geojson
python src/filter_grid.py --sgis-dir "SGIS 원본의 1. 통계 폴더 경로"
```

SGIS 원본 통계는 저장소에 포함되어 있지 않습니다. 원본 파일이 없거나 필터 결과가 비면 기존 공유 CSV·GeoJSON을 보존하고 중단하도록 수정했습니다. 통계값 누락은 0으로 채우지 않으며, 인구 미확인 격자의 제외 개수를 표시합니다.

## 통계 해석

`pop_1km`, `hh_1km`, `single_hh_1km`는 500m 격자 자체의 값이 아니라 **상위 1km 격자의 값**입니다. 같은 1km 값을 여러 500m 격자가 공유하므로 500m 행을 그대로 합산하면 중복됩니다. 현재 파일에는 고유 1km 코드가 662개 있습니다. 인구가 있는 1km 범위에 속한다고 해서 해당 500m 격자에 실제 거주자가 있다는 뜻은 아닙니다.

기존 공유 결과의 가구·1인가구 값에는 이전 코드의 0 기본값 처리가 적용되었습니다. SGIS 원본이 없어 기존 0이 실제 관측값인지 누락 대체값인지 재확인하지 못했습니다. 이 통계를 별도의 지표로 사용하려면 원본을 확보해 수정한 코드로 재생성해야 합니다. 기존 결과 파일의 수치를 추측해 수정하지 않았습니다.

## 주소 검색

`.env.example`을 참고해 로컬 `.env`에 `KAKAO_REST_KEY`를 설정합니다. 빈 예시 파일만 Git에 공유됩니다.

```bash
python src/locate.py "춘천시청"
```

키를 사용하지 않는 좌표 변환·3×3 격자 계산과 모의 API 응답 처리를 검증했습니다. 실제 카카오 API 호출은 별도 키가 필요하며 이번 통합 검증에서는 수행하지 않았습니다. 주소 검색 결과가 춘천 밖일 수 있으므로 최종 화면에서는 춘천 경계 포함 여부를 검사해야 합니다.

## 다음 연결 작업

시설 분류 파일에 `grid_id`를 붙이고 선택한 세부 시설·3×3 범위로 공간 집계한 뒤 접근성 점수를 계산합니다. 시설 선택 컴포넌트와 점수 집계 함수는 준비되어 있지만 이 연결과 최종 화면은 아직 구현할 작업입니다. 경계 밖이거나 자료가 없는 격자는 시설 0개로 단정하지 않습니다.

팀원이 추가한 HTML·CSS·JavaScript 화면은 `app/app/index.html`에 있으며 카카오 지도와 주소/장소 검색 코드가 있습니다. 시작 버튼이 실제 지도 요소를 가리키도록 연결 오류를 수정했습니다. 이 화면과 Python 분석 함수는 아직 연결 전이며, 함께 올라온 `app/app/streamlit_app.py`는 빈 파일입니다.
