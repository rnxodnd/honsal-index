# 혼살지수 개발 계획

**마감 반영:** 개발 기간은 2026-10-30 13:00 ~ 2026-10-31 12:00(KST), 팀은 4명, 제출물은 실행 가능한 프로그램과 발표자료입니다. 아래는 전체 설계 방향이며, 이번 작업의 범위·역할·시간 배분은 [23시간 완성 계획](23-hour-plan.md)을 우선합니다. 다도시 확장과 AI 질의응답은 이번 마감의 필수 기능이 아닙니다.

## 기획안에서 확인한 목표

강원도 읍·면·동의 생활 편의를 0~100점으로 비교하고, 사용자 조건에 맞는 동네와 추천 근거를 제공합니다. 주민의 정착 선택과 지자체의 생활 인프라 개선 판단을 돕는 것이 목적입니다.

기획안의 주요 사용자는 청년·무차량·여성·고령 1인 가구 및 지자체 담당자입니다. 핵심 흐름은 **조건 입력 → 지도 탐색 → 동네 비교 → 맞춤 추천**입니다.

기획안은 춘천·원주·강릉 중 2~3개 시·군에서 시작하는 MVP를 제안합니다. 개발 과정에서는 우선 1개 도시에서 전체 계산 흐름을 검증하고 범위를 넓히는 방식을 제안합니다. 첫 도시는 아직 확정하지 않았습니다.

## 기본 점수 구성

| 항목 | 기획안 비중 | 필요한 자료의 예 | 설계할 평가 방법 |
| --- | ---: | --- | --- |
| 생활시설 | 25% | 편의점·마트·세탁소·은행·식당 위치 | 거주지 기준 도보 접근성 |
| 교통 | 20% | 정류장·노선·배차 간격 | 정류장 접근성과 실제 이동 가능성 |
| 의료 | 15% | 병원·약국·응급실 위치·운영시간 | 거리·이동시간 및 시간대별 이용 가능성 |
| 안전 | 15% | 가로등·CCTV·안전시설 위치 | 안전 관련 인프라 접근성 |
| 주거 부담 | 15% | 전월세 실거래·공공임대·소득·생활비 | 비용 부담이 낮을수록 높은 점수 |
| 여가·커뮤니티 | 10% | 공원·도서관·체육·문화시설·운영시간 | 이용 가능한 시설 접근성 |

모든 항목을 먼저 **높을수록 생활 여건이 좋은 0~100점**으로 변환한 다음 다음과 같이 합산합니다.

```text
종합점수 = 생활시설 × 0.25 + 교통 × 0.20 + 의료 × 0.15
         + 안전 × 0.15 + 주거부담 완화 × 0.15 + 여가 × 0.10
```

기본 비중은 `config/weights.json`에 보관합니다. 검증된 측정 척도가 아니라 기획안에서 출발한 초기 설계입니다. 개인화 가중치는 음수를 허용하지 않고, 합계가 0보다 클 때 합계 1로 재조정합니다. 모든 가중치가 0이면 다시 입력하도록 안내합니다.

## 계산 전에 확정할 사항

- **지역 기준:** 행정동·법정동의 차이를 확인하고, 동일 기준일의 행정코드와 경계를 사용합니다. 지역명만으로 데이터를 합치지 않습니다.
- **공간 집계:** 읍·면·동 전체 시설 수를 도보 접근성으로 해석하지 않습니다. 거주지 또는 주거 격자에서의 접근성을 구한 뒤 지역별 집계 방식을 정합니다.
- **거리·시간:** 직선거리를 실제 도보 10분으로 표시하지 않습니다. 경로 자료가 없으면 사용한 거리 기준과 추정 방식을 명시합니다.
- **방향성:** 주거비·의료 거리·배차 간격은 작을수록 유리합니다. 원자료 값과 최종 점수 방향을 구분합니다.
- **정규화:** 도시가 추가되어도 비교가 가능한 기준을 정하고 버전을 기록합니다. 도시마다 별도로 계산한 상대점수를 그대로 합쳐 순위를 만들지 않습니다.
- **결측:** 자료 없음과 실제 시설 0개를 구분합니다. 검증 전에는 필요한 항목이 없는 지역의 종합점수를 산출하지 않는 보수적인 방식을 기본안으로 둡니다. 데이터 충족률과 누락 항목을 함께 표시합니다.
- **안전 지표:** 가로등·CCTV 수는 안전 관련 인프라 지표로 설명하며, 실제 범죄 위험을 직접 측정한 점수로 표현하지 않습니다.
- **주거 지표:** 개인 소득인지 지역 평균 소득인지 구분합니다. 소득 자료를 확보하지 못하면 실제 비용 자료에 맞게 지표 정의를 수정합니다.
- **기본점수·개인화:** 두 점수를 화면에서 구분하고, 비교할 때 같은 가중치·기준일·계산 버전을 적용합니다.
- **추천 설명:** 추천 사유와 약점은 계산된 항목에서 생성합니다. 기획안의 예시 지역 점수는 실제 관측 데이터로 사용하지 않습니다.

## 필수 기능: 3×3 격자 생활권 점수

분석 단위는 500m × 500m 격자이며, 점수는 선택한 격자를 가운데 둔 3×3 격자(1,500m × 1,500m) 생활권 기준으로 계산합니다. 이 기능은 최종 프로그램에 반드시 포함합니다.

1. 격자 선택: 사용자가 지도에서 격자를 클릭하거나 주소를 입력하면, 주소 좌표가 속한 격자를 선택합니다.
2. 생활권 설정: 선택한 격자와 주변 8개 격자를 합친 3×3 격자(9개)를 생활권으로 정합니다.
3. 화면 표시: 9개 격자와 그 안의 생활·의료·교통·여가 시설을 지도와 목록으로 보여줍니다.
4. 점수 계산: 9개 격자 안 시설 데이터만 사용해 항목별 점수와 가중치를 계산합니다.

### 구현 규칙

- 격자 ID는 `G500_{x0}_{y0}` 형식이며, `x0`, `y0`는 격자 왼쪽 아래 모서리의 EPSG:5179 좌표(미터)입니다.
- 시설 좌표의 격자 ID는 EPSG:5179로 변환한 뒤 `G500_{x//500*500}_{y//500*500}`로 계산합니다.
- 주변 8개 격자 ID는 가운데 격자의 `x0`, `y0`에 ±500을 더해 계산합니다.
- 모든 시설 데이터에 `grid_id` 컬럼을 붙여 `data/processed/`에 저장합니다. 인구가 없어 지도에서 뺀 격자의 시설도 삭제하지 않습니다(3×3 계산에 포함될 수 있음).
- 춘천 경계 밖이라 데이터가 없는 칸은 비어 있다고 표시합니다.
- 주소 입력에는 주소 → 좌표 변환(지오코딩) API가 필요합니다. 후보: 카카오 로컬, 브이월드, 도로명주소 API.
- 발표·화면 표현은 "반경" 대신 "선택 지점 중심 1.5km × 1.5km 생활권"으로 씁니다.

```python
def neighbors_3x3(grid_id, size=500):
    _, x0, y0 = grid_id.split("_")
    x0, y0 = int(x0), int(y0)
    return [f"G{size}_{x0 + dx * size}_{y0 + dy * size}"
            for dy in (-1, 0, 1) for dx in (-1, 0, 1)]
```

### 관련 파일

- `src/make_grid.py`: 춘천 500m 격자 생성 → `data/processed/grid_500m.*`
- `src/filter_grid.py`: SGIS 1km 인구 기준 거주 격자 필터링 → `data/processed/grid_500m_filtered.*` (인구·가구·1인가구는 1km 격자 값)
