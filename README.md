> 혼자 살아도 더 편안한 동네를 찾다.

**춘천 1인 가구를 위한 생활 편의 점수·동네 비교·맞춤 추천 서비스**

현재 `codex/ui-facility-results`는 기존 화면 디자인에 점수 API를 연결한 테스트 브랜치입니다. 위치·시설 선택을 바꾸면 실제 점수와 주변 시설 전체 목록을 자동으로 갱신합니다. 백엔드 API는 PR #2로 `main`에 병합되었지만, 이번 UI 연결은 아직 `main`과 Netlify 배포 화면에 반영하지 않았습니다. [프론트엔드 API 테스트 안내](docs/frontend-api-test.md)에 따라 로컬에서 확인합니다.

## 해결하려는 문제

1인 가구가 동네를 선택하려면 생활시설, 대중교통, 의료시설, 여가시설의 위치를 따로 확인해야 합니다. 같은 동네라도 사용자가 자주 이용하는 시설 종류에 따라 편의가 달라집니다.

혼살지수는 이러한 정보를 비교 가능한 지표로 정리하여 다음 질문에 답하고자 합니다.

- 차량 없이 생활하기 편한 동네는 어디일까?
- 의료시설과 생활시설을 이용하기 좋은 동네는 어디일까?
- 내가 중요하게 생각하는 조건에 맞는 동네는 어디일까?
- 지역별로 어떤 생활 인프라를 개선해야 할까?

## 점수 설계

현재 분석 범위는 **생활시설·의료·교통·여가시설 네 항목**입니다. 안전성·주거 부담·별도 생활서비스 항목은 이번 구현에서 제외합니다. 생활시설(편의시설) 11종과 여가시설 15종은 2026년 9월 상권 데이터에서 춘천 소재 업소만 분류했습니다. 시설 수와 컬럼 정의는 [편의·여가시설 데이터](docs/commerce-data.md)에 정리했습니다.

사용자가 선택한 시설 종류별 접근성을 **높을수록 이용 여건이 좋은 0~100점**으로 변환하고, 같은 항목 안에서 평균을 낸 뒤 항목별 가중합을 계산합니다. 예를 들어 여가시설에서 당구장과 볼링장만 선택하면 탁구장은 지도·여가 점수·추천 근거에 반영하지 않습니다.

| 평가 항목 | 기본 가중치 | 평가 내용 |
| --- | ---: | --- |
| 생활시설 | 30% | 상권 자료에서 선택한 편의점·슈퍼마켓 등 이용 여건 |
| 의료 | 20% | 선택한 의료기관·약국 이용 여건 |
| 교통 | 40% | 선택한 버스 정류장·전철/기차역 접근성 |
| 여가시설 | 10% | 상권 자료에서 선택한 당구장·볼링장·탁구장 등 이용 여건 |

```text
유형별 점수 = max(0, 100 × (1 - 최근접 거리(m) / 750))
항목별 점수 = 선택한 유형별 점수의 평균
종합점수 = 생활시설 × 0.3 + 의료 × 0.2 + 교통 × 0.4 + 여가시설 × 0.1
```

위 비중은 사용자가 정한 프로젝트 기본값이며 검증된 측정 척도는 아닙니다. 거리는 입력 위치가 속한 **격자 중심부터 시설까지의 직선거리**로 계산합니다. 유형을 하나도 선택하지 않은 항목은 제외하고 나머지 가중치 합계를 1로 맞춥니다. 선택한 유형의 시설이 주변 3×3에 없는 경우는 해당 유형을 0점으로 유지합니다. 미확보 유형이나 잘못된 자료는 오류로 구분하며, 전체 시설을 하나도 선택하지 않으면 분석하지 않습니다.

가중치는 `config/weights.json`, 거리 산식은 `src/scoring/accessibility.py`, 항목 평균·합산은 `src/scoring/preferences.py`에서 수정할 수 있습니다. API 요청·응답 형식을 유지하면 기존 연결을 활용할 수 있습니다. 거리 기준을 늘릴 때는 검색 격자 범위도 함께 검토하고, 변경 후 테스트·서버 재시작 및 점수 설명 갱신이 필요합니다.

### 데이터와 계산 원칙

- 자료가 없다는 이유로 해당 항목을 0점 처리하지 않습니다.
- 상권 자료의 세부 업종 코드·명칭을 보존하고, 선택한 시설 종류만 계산에 사용합니다. 시설 수가 많은 업종이 다른 업종을 압도하도록 원자료 개수를 단순 합산하지 않습니다.
- 같은 순위에서 비교하는 지역에는 동일한 평가 항목과 계산 기준을 적용합니다.
- 확보하지 못한 평가축은 제외 여부를 표시하고, 사용하는 가중치의 합을 100%로 조정합니다.
- 일부 평가축만 사용한 결과는 ‘확보된 항목 기반 시범 점수’로 표시합니다.
- 데이터 출처·기준일과 계산 방식을 함께 제공합니다.
- 테스트용 가상 데이터와 실제 지역 데이터를 구분합니다.

## 개발 환경 설치

**Python 3.12와 Git을 먼저 설치합니다.** `.venv/`는 각자의 컴퓨터에서 만들고 GitHub에는 올리지 않습니다. 공유하는 `requirements.txt`로 같은 패키지 버전을 설치합니다. 아래 Clone 명령은 처음 내려받을 때만 사용하며, 이미 Clone했다면 해당 폴더에서 가상환경 생성 단계부터 진행합니다.

macOS / Linux:

```bash
git clone https://github.com/rnxodnd/honsal-index.git
cd honsal-index
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pip check
.venv/bin/python -c "import sys, streamlit, pandas; assert sys.version_info[:2] == (3, 12); assert sys.prefix != sys.base_prefix; print('Python:', sys.version.split()[0]); print('Streamlit:', streamlit.__version__); print('pandas:', pandas.__version__)"
```

Windows PowerShell:

```powershell
git clone https://github.com/rnxodnd/honsal-index.git
cd honsal-index
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -c "import sys, streamlit, pandas; assert sys.version_info[:2] == (3, 12); assert sys.prefix != sys.base_prefix; print('Python:', sys.version.split()[0]); print('Streamlit:', streamlit.__version__); print('pandas:', pandas.__version__)"
```

위 명령은 가상환경의 Python을 직접 사용하므로 별도 활성화가 필요 없습니다. 이미 `.venv`가 있다면 먼저 해당 Python의 `--version`으로 3.12인지 확인합니다. 다른 버전의 환경에 덮어 설치하지 않습니다.

VS Code에서는 프로젝트 폴더를 연 뒤 명령 팔레트의 **Python: Select Interpreter**에서 `.venv`의 Python 3.12를 선택합니다. 공유 설정에 기본 경로가 포함되어 있지만, 기존에 다른 인터프리터를 선택한 PC에서는 직접 다시 선택해야 합니다.

## UI와 백엔드 함께 실행

테스트 브랜치의 작업 폴더에서 실행합니다. macOS / Linux:

```bash
.venv/bin/python -m uvicorn src.api:app --host 127.0.0.1 --port 5500 --reload
```

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe -m uvicorn src.api:app --host 127.0.0.1 --port 5500 --reload
```

브라우저에서 <http://127.0.0.1:5500>을 열고 시설 종류를 선택하면 점수·개수·상호명 목록이 자동으로 표시됩니다. 처음에는 아무 시설도 선택하지 않습니다. 선택 위치나 시설이 바뀌면 다시 분석하며, 계산 중·오류·전체 선택 해제 시 이전 결과를 지웁니다. 개발자 도구 콘솔에 코드를 붙여넣을 필요는 없습니다.

현재 개발 PC의 별도 폴더 `honsal-index-api-test`에서 기존 가상환경을 쓰려면 `.venv/bin/python` 대신 `../honsal-index/.venv/bin/python`을 사용합니다. 팀원은 각자 Python 3.12 가상환경을 만듭니다. `main`만 Pull해서는 이번 UI 변경을 받을 수 없습니다. `codex/ui-facility-results` 테스트 브랜치에서 확인합니다.

<http://127.0.0.1:5500/api/health>에서 API 준비 상태를 확인합니다. 지도와 주소 검색에는 카카오 JavaScript 키의 등록 도메인 설정이 필요합니다. 지도 SDK가 작동하지 않아도 기본 위치의 점수 API 요청은 사용할 수 있습니다. Windows·Linux 실제 설치는 각 팀원 PC에서 확인해야 합니다.

API만 별도로 실행하려면 `src.public_api:app`을 8001 포트에서 사용합니다. 이 진입점은 UI·CSV 파일을 제공하지 않습니다. Netlify 기본 허용 출처는 `https://unique-dusk-66f82f.netlify.app`이며, 다른 출처는 `HONSAL_ALLOWED_ORIGINS`로 지정합니다. 별도 HTTPS API와 정적 화면 연결 방법은 [프론트엔드 API 테스트 안내](docs/frontend-api-test.md)에 있습니다. 현재 Netlify 배포 화면은 이번 UI 연결을 포함하지 않습니다.

```bash
.venv/bin/python -m unittest discover -s tests -v
```

현재 Python 테스트 65개가 통과했습니다. 춘천시청 인근 좌표(`127.7298`, `37.8813`)에서 당구장·볼링장만 선택한 실제 데이터 요청은 67.8점, 주변 해당 시설 12개를 반환합니다. UI는 이 12개를 모두 표시하며 같은 상호명·유형·좌표라도 시설 ID가 다르면 개별 시설로 유지합니다. 점수 산식은 기존의 유형별 최근접 거리 방식을 유지합니다.

Netlify 배포는 `netlify.toml`의 `app` → `dist` 빌드를 사용합니다. Netlify의 빌드 환경변수 `HONSAL_API_BASE_URL`에 실행 중인 HTTPS 백엔드 주소를 넣고 배포합니다. 자세한 Git 연동·수동 업로드 절차는 [프론트엔드 API 테스트 안내](docs/frontend-api-test.md)를 참고합니다.
