# 혼살지수 팀 역할 분담

사용자가 정한 담당 분야를 기준으로 구성합니다. 개발 기간은 **2026-10-30 13:00 ~ 2026-10-31 12:00(KST)**이며, 필수 제출물은 **실행 가능한 프로그램과 발표자료**입니다.

## 역할과 책임

| 구성원 | 담당 | 구체적인 작업 | 최종 산출물 |
| --- | --- | --- | --- |
| 팀장 | 백엔드·기술 통합 | 데이터 입출력 형식 합의 주도, 지표 표준화, 가중치·종합점수 계산, 순위·추천 근거 생성, 예외 처리, 코드 병합·실행환경 관리 | 검증된 계산·추천 모듈, 실행 가능한 통합 프로그램 |
| 팀원 1 | 기획·발표·사용자 검증 | 대상 사용자와 시연 흐름 정리, 제출 규정 확인, 데이터 출처 조사 지원, 화면 사용성 점검, 오류 재현 기록, 발표자료·대본·실행 안내 작성, 제출 관리 | 발표자료, 시연 대본, 사용자 검증 기록, 제출 패키지 목록 |
| 팀원 2 | 프론트엔드 | 지역 선택, 지도, 종합·항목별 점수, 두 동네 비교, 가중치 입력, 추천 목록, 출처·기준일·결측 안내, 백엔드 결과 연결 | 전체 사용자 흐름이 작동하는 화면 |
| 팀원 3 | 데이터 | 실제 자료 수집·정제, 지역 코드와 좌표 통일, 중복·결측 처리, 비교 가능한 지역 집계, 출처·기준일 기록 | 정제 데이터, 재실행 가능한 처리 코드, 데이터 설명 |

팀장은 백엔드와 코드 통합을 맡으며, 발표자료 제작과 데이터 수집은 각 담당자가 책임집니다. 팀원 1은 오류를 발견하고 재현 절차를 기록하며, 수정은 해당 기능 담당자가 수행합니다. 팀원 2가 계산 결과와 화면을 연결하고, 팀장이 전체 코드의 기술적 통합을 확인합니다.

## 작업 파일과 브랜치

아래 경로는 앞으로 구현할 파일의 소유 범위입니다. 파일이 이미 구현되었다는 뜻은 아닙니다.

| 구성원 | 기본 작업 범위 | 작업 브랜치 |
| --- | --- | --- |
| 팀장 | `src/scoring/`, `src/recommendation/`, `config/`, 계산 검증, 의존성 목록·실행 설정 | `codex/backend` |
| 팀원 1 | `docs/`, `presentation/`, `README.md` | `codex/planning` |
| 팀원 2 | `app/` | `codex/frontend` |
| 팀원 3 | `src/data/`, `data/`, 데이터 탐색 노트북 | `codex/data` |

- 다른 담당 영역을 수정해야 할 때는 담당자와 먼저 조율합니다.
- 새 라이브러리가 필요하면 팀장에게 전달하여 공용 의존성 목록에 반영합니다.
- 데이터 컬럼명이나 함수 입출력 변경은 팀장·팀원 2·팀원 3이 함께 확인합니다.
- 각자 자기 기능을 검증한 뒤 Pull Request를 만들고, 팀장이 통합 결과를 확인합니다.
- 팀장 본인의 변경도 영향을 받는 담당자가 확인합니다. 데이터·수치는 팀원 3, 화면 연결은 팀원 2가 검토합니다.
- 팀원 1이 핵심 사용 흐름을 확인한 뒤 시연 가능한 통합본을 기록합니다.

## 담당별 작업 체크리스트

- [ ] 평가 항목을 동일 방향의 0~100점으로 변환한다.
- [ ] 기본·사용자 가중치, 종합점수, 순위, 최대 5곳 추천을 구현한다.
- [ ] 추천 이유를 실제 계산된 강점·약점에서 생성한다.
- [ ] 가중치 합계 0, 누락 데이터, 후보 지역 부족을 처리한다.
- [ ] 검산 가능한 작은 사례로 계산 결과를 확인한다.
- [ ] 통합 코드와 의존성을 관리하고 다른 PC에서의 실행 문제를 담당자와 해결한다.

### 팀원 1: 기획·발표·사용자 검증

- [ ] ‘동네 선택 → 점수 확인 → 두 동네 비교 → 가중치 변경 → 추천 확인’ 시나리오를 작성한다.
- [ ] 16:00까지 팀원 3의 출처·기준일·자료 제공 범위 조사를 지원한다.
- [ ] 18:00부터 실제 기능을 기준으로 발표자료를 구성한다.

- [ ] 두 동네를 동일 항목으로 비교한다.
- [ ] 가중치 입력을 백엔드에 전달하고 결과를 갱신한다.

- [ ] 빈 결과, 입력 오류, 지도 연결 실패 상황을 처리한다.

## 범위 조정과 문제 대응

- 한 도시의 실제 데이터를 이용한 지도·비교·개인화 추천을 필수 범위로 유지합니다.
- 16:00에 자료가 확보되지 않은 평가축은 팀장과 팀원 3이 함께 결정하고, 팀원 2는 화면에, 팀원 1은 발표에 그 범위를 반영합니다.
- 자료 문제는 팀원 3, 산식·추천 문제는 팀장, 화면 문제는 팀원 2가 수정합니다. 팀원 1은 수정 후 같은 시나리오로 재확인합니다.
- AI 챗봇, 추가 도시, 복잡한 디자인은 핵심 시연이 완성된 뒤에만 검토합니다.
- 00:30 이후에는 새 기능을 추가하지 않고 결함 수정과 제출 준비에 집중합니다.
